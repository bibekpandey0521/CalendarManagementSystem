3. DATABASE DEPLOYMENT (SSDT)
================================================================================

The database project is located at:
    Database/CalendarManagement.Database.sqlproj

It can be deployed three ways:

--------------------------------------------------------------------------------
OPTION A: Visual Studio 2022 (Recommended)
--------------------------------------------------------------------------------

STEP 1: Open Visual Studio 2022 (with SQL Server Data Tools workload installed).

STEP 2: File -> Open -> Project/Solution ->
        Select: Database/CalendarManagement.Database.sqlproj

STEP 3: Expand Deployment/ and open CalendarManagement.Database.publish.xml.
        Set:
        TargetServerName: (localdb)\MSSQLLocalDB
        TargetDatabaseName: CalendarManagementDb

STEP 4: Right-click the project -> Publish... ->
        Select profile -> Publish

STEP 5: Generate DACPAC (optional):
        Right-click project -> Publish -> Generate Script
        Or use SqlPackage.exe:
        SqlPackage.exe /a:Extract /sfn:"Database\bin\Debug\CalendarManagement.Database.dacpac" /tfn:"CalendarManagementDatabase.dacpac"

--------------------------------------------------------------------------------
OPTION B: Command Line (sqlcmd) - No Visual Studio Required
--------------------------------------------------------------------------------

STEP 1: Create the database if it doesn't exist:
    sqlcmd -S "(localdb)\MSSQLLocalDB" -E -d master -Q "IF DB_ID(N'CalendarManagementDb') IS NULL CREATE DATABASE CalendarManagementDb;"

STEP 2: Deploy the full schema (tables, procedures, functions, indexes):
    sqlcmd -S "(localdb)\MSSQLLocalDB" -E -d CalendarManagementDb -I -b -i "Database/Scripts/Deploy-Database.sql"

STEP 3: Seed lookup data (EventTypes, EventCategories, EventStatuses):
    sqlcmd -S "(localdb)\MSSQLLocalDB" -E -d CalendarManagementDb -I -b -i "Database/Scripts/Post-Deployment.sql"

STEP 4: Verify deployment:
    sqlcmd -S "(localdb)\MSSQLLocalDB" -E -d CalendarManagementDb -Q "SELECT name FROM sys.tables ORDER BY name;" -h -1 -W

IMPORTANT: Always use the -I flag with sqlcmd to enable QUOTED_IDENTIFIER.
Without it, filtered indexes will fail with Msg 1934.

--------------------------------------------------------------------------------
OPTION C: MSBuild - Build Without Deploying
--------------------------------------------------------------------------------

msbuild Database\CalendarManagement.Database.sqlproj /p:Configuration=Debug /p:Platform=AnyCPU

Output: Database\bin\Debug\CalendarManagement.Database.dacpac

4. BACKEND DEPLOYMENT (ASP.NET CORE WEB API)
================================================================================

STEP 1: Create the Project
    cd C:\Users\bibek.pandey\source\repos\CalendarManagementSystem
    mkdir backend\CalendarManagement.Api
    cd backend\CalendarManagement.Api
    dotnet new webapi --name CalendarManagement.Api --force

STEP 2: Add NuGet Packages
    dotnet add package Microsoft.Data.SqlClient
    dotnet add package Swashbuckle.AspNetCore --version 10.3.1
    dotnet add package Microsoft.Extensions.Diagnostics.HealthChecks

STEP 3: Configure appsettings.json
    {
      "ConnectionStrings": {
        "DefaultConnection": "Server=(localdb)\\MSSQLLocalDB;Database=CalendarManagementDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=True"
      },
      "Cors": {
        "AllowedOrigins": [
          "http://localhost:3000",
          "http://127.0.0.1:3000"
        ]
      }
    }

STEP 4: Build & Run
    dotnet build
    dotnet run

API will be available at: http://localhost:5050
Swagger UI: http://localhost:5050/swagger
Health check: GET http://localhost:5050/health

5. FRONTEND DEPLOYMENT (NEXT.JS)
================================================================================

STEP 1: Create the Project
    cd C:\Users\bibek.pandey\source\repos\CalendarManagementSystem\frontend
    npx create-next-app@latest calendar-management-ui --yes --ts --tailwind --app-dir --eslint --import-css
    cd calendar-management-ui

NOTE: Next.js package names cannot contain capital letters, so use
      calendar-management-ui (lowercase with hyphens).

STEP 2: Install Dependencies
    # FullCalendar
    npm install @fullcalendar/react @fullcalendar/daygrid @fullcalendar/timegrid @fullcalendar/list --legacy-peer-deps

    # Axios for API calls
    npm install axios --legacy-peer-deps

    # Shadcn UI primitives
    npm install @radix-ui/react-slot clsx tailwind-merge lucide-react --legacy-peer-deps

    # Tailwind CSS v4
    npm install -D tailwindcss @tailwindcss/postcss --legacy-peer-deps

STEP 3: Configure Tailwind v4
    # tailwind.config.js
    module.exports = {
      content: ["./app/**/*.{js,ts,jsx,tsx}", "./components/**/*.{js,ts,jsx,tsx}"],
      theme: { extend: {} },
      plugins: []
    };

    # postcss.config.js
    module.exports = {
      plugins: { "@tailwindcss/postcss": {} }
    };

STEP 4: Run the Frontend
    npm run dev --webpack

Frontend will be available at: http://localhost:3000

WARNING: Use --webpack flag. Next.js 16 uses Turbopack by default, which has
         compatibility issues with @fullcalendar/core subpath exports.
         Always use --webpack for development.

8. TROUBLESHOOTING
================================================================================

Issue                                 Solution
-------------------------------------------------------------------------------
LocalDB not running                   sqllocaldb start MSSQLLocalDB
Filtered indexes fail (Msg 1934)      Use -I flag with sqlcmd to enable QUOTED_IDENTIFIER
FullCalendar/Turbopack errors         Run frontend with npm run dev --webpack
PUT/DELETE return 404                 Fixed: code falls back to @@ROWCOUNT when ExecuteNonQuery returns -1 (SET NOCOUNT ON)
Database connection fails             Verify connection string in backend/CalendarManagement.Api/appsettings.json
Port 5050 or 3000 in use              Kill existing processes: Get-Process -Name dotnet | Stop-Process -Force
